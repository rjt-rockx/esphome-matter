# Reproduction: covers & access (blinds, garage, locks, valves)

Branch `repro-access`, examples in `examples/devices/covers-access/` (31 validate, 9 blocked ones in `_gaps/`).
Method: YAML -> `esphome compile --only-generate` with `MATTER_LAYOUT_JSON` -> `python -m tools.conformance <yaml> --emit-dump` -> structural diff against the real dump (`/home/user/research/devices/tools/repro_diff.py`, WindowCovering feature map patched in by hand, see "Tool limits").
Evidence: dump = HA fixture; doc/inferred = catalog row only. Yale, Nuki, SwitchBot, Meross, Eve Aqua have NO cluster data anywhere (DCL device-type id only), so they are modelled on the nearest real dump and marked inferred.

## YAML UX notes
- `expose:` needs `as:` for everything beyond switch/light/temperature/humidity, so the shortest honest lock/cover/valve config is `{id: x, as: window_covering}` (works, 1 line). Valid but verbose compared with `endpoints:` once `label:`, `features` and `options` are added.
- Errors name keys well for typos (`boolean_state` for contact sensor, label length) but the conformance crash (G2) is opaque and names no feature.
- Door Lock `with_features` uses display names with spaces (`PIN Credential`) while cluster-level features use snake_case; the Closure device type takes yet another form; easy to get wrong.
- Hash-numbered endpoints make every comparison with a real device endpoint-number-agnostic; useful, but a user mirroring a device must pin (`endpoint: 1`).
- ESP32 classic strapping pins (GPIO4/5) and USB-JTAG pins (GPIO12/13 on C6) warn in examples: not component related.
- Default lock/cover/valve inference: a garage-class cover is refused with a helpful message that points at Closure, but no escape hatch is offered; the template-cover mirror trick is the only way.

## Tool limits seen
- `layout_dump` does not export tags, labels, parents or TagList, and WindowCovering features are trait-derived at runtime (empty in the layout); my diff patches the WC feature map by hand (LF+PA_LF, +TL+PA_TL for tilt covers). `tools/conformance` baseline still claims the TagList gap that the merged base already fixes (known_gaps entry is stale: it fires on `endpoints:` variants only).
- `repro_diff.py` pairs endpoints by order, so hashed numbers show as swapped pairs for expose variants.
- Base merge: `git merge sdk-gaps t08-expose` conflicts (endpoints.py, test_conformance.py). I resolved by keeping the base and renaming sdk-gaps' test to `tests/unit/test_conformance_tool.py`. `components/matter/expose/inference.py` imports `CONF_FEATURES` from `const` which no longer exists; I applied a 2-line local fix (uncommitted) so expose works.
- I also merged `tool-devicediff` before being told not to; the merge commit is on the branch (could not be undone: hard reset denied).
